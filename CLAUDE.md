# Music Grabber — пам'ятка для AI-агентів

Читай першим, перш ніж щось міняти. Файл у git навмисно: власник працює з
кількох комп'ютерів, і правила мусять їхати разом із кодом. Репо **публічне**
(GitHub `Toksa88/yt`) — жодних секретів, токенів, адрес серверів і особистих
шляхів ні тут, ні в документації, ні в комітах.

## Спільні правила воркспейсу

Блок однаковий у репо власника (міняєш правило — міняй усюди). Частини, що стосуються
серверної інфраструктури інших репо, тут прибрано: цей репо публічний, а
Music Grabber — настільний застосунок без VPS і баз.

- **Мова** — українська: спілкування, коментарі, документація, тексти інтерфейсу.
- **Git**: у комітах і PR **не згадувати AI/Claude** — жодних `Co-Authored-By: Claude`,
  «Generated with …». Повідомлення лише про суть зміни, у стилі `git log` цього репо.
  Комітити й пушити — коли власник просить; злиття PR — його рішення.
- **Сервери власника** (ssh/scp на будь-який VPS воркспейсу): навіть лише читання — тільки
  після явного дозволу власника в чаті, щоразу окремо. До цього репо це не належить, але
  правило діє, якщо задача раптом туди зайде.
- **Секрети**: `.env`, токени, паролі не виводити в чат, не комітити, не вставляти в URL.
  Тут це передусім `GH_TOKEN` для релізу — лише змінна середовища на час команди.
- **Windows-розробка**: у Git Bash heredoc із кирилицею чи `\n` у Python-рядках псується —
  правити файли інструментом редагування, а не `sed`/`python -` з heredoc. Вивід Python з
  кирилицею — з `PYTHONIOENCODING=utf-8`. Повідомлення коміту — через файл (`git commit -F`).
- **Перевіряти самому до «готово» — завжди** (вимога власника 25.09.2026): поведінку, а не
  лише компіляцію. Тут: `npm run test:fast`; для змін інтерфейсу чи завантаження — ще й
  `test:live`, а UI — у справжньому вікні (`npm start`, консоль без помилок, `MG_SHOTS`).
  У звіті — чесно: що перевірено, що ні.
- **Пам'ятка для наступного агента — завжди.** Після кожної змістовної зміни онови цей файл
  у тому ж коміті: нове правило чи інваріант, пастка, на яку наступив, рішення власника і
  чому, крок, що лишився за власником. Коротко, без переказу коду й історії git. Застаріле —
  виправ або прибери одразу, а не дописуй поруч. Секретів сюди не писати.

## Що це

Настільний музичний застосунок для Windows (Electron 33, Node 20+, інтерфейс
українською): пошук по YouTube Music / YouTube / SoundCloud / iTunes /
MusicBrainz, прослуховування потоком, завантаження через **yt-dlp + FFmpeg**
з тегами й вшитою обкладинкою, Сховище (теги читаються з файлів), плейлисти,
улюблене, статус у Discord. Версія — у `app/package.json` (зараз 1.0.1;
релізи — GitHub Releases, автооновлення через `electron-updater`).

Людська документація: [README.md](README.md) (що вміє, як встановити й
запустити) і [ARCHITECTURE.md](ARCHITECTURE.md) (модулі, схеми, IPC, дані,
правила). Не дублюй їх тут — оновлюй там, а сюди клади лише те, що потрібне
агентові.

## Як працювати

Усе — з теки `app/` (або `--prefix app`). Залежності й `app/bin` вже можуть
бути встановлені; `app/bin/` і `node_modules/` у `.gitignore`.

```bash
npm install --prefix app        # залежності
npm run bins --prefix app       # yt-dlp та ffmpeg у app/bin (чужі бінарники, не в git)
npm start --prefix app          # запуск (або подвійний клік по "Music Grabber.bat")
npm run test:fast --prefix app  # герметичні тести, кілька секунд, без мережі
npm run test:live --prefix app  # справжнє завантаження + вікно через DevTools, повільно
npm run build --prefix app      # NSIS-інсталятор у app/dist
```

- Збирача й лінтера немає: рядки `app/src/**` виконуються як є. Вікно — один
  `renderer/app.js` без модулів (чому — в ARCHITECTURE.md).
- Профіль при запуску з вихідних кодів — `%APPDATA%\music-grabber`, у
  встановленої програми — `%APPDATA%\Music Grabber`. **Не чіпай робочі
  `playlists.json`/`personal.json` власника** під час перевірок; живі тести
  мають власний профіль `mg-test-profile`.
- `app/package-lock.json` часто лишається зміненим після локального `npm install`
  — **не коміть його** без явної причини.
- Відлагодження вікна: `MG_DEBUG=1` (помилки вікна в консоль), `MG_SHOTS=<тека>`
  (знімки в UI-тесті).

## Інваріанти й пастки

Докладніше з поясненнями — в ARCHITECTURE.md, розділ «Правила, які дорого
відкривати заново». Коротко, що не можна ламати:

- **Вікно ізольоване**: `contextIsolation`, без `nodeIntegration`, CSP в
  `index.html`. Нова можливість, що чіпає диск чи мережу, = `handle()` у
  `main.js` + рядок у `preload.js`. Усі обробники повертають `{ok,data}` /
  `{ok:false,error}` через `handle()`.
- **Прапорці yt-dlp (`buildArgs`)** — кожен закриває конкретну поломку
  (webp-обкладинка, webm без обкладинки, артисти через кому). Міняти лише з
  перевіркою файлу на диску й оновленням `args.test.js`. Не «лікувати» 403
  іншим клієнтом YouTube.
- **Жодних синхронних викликів зовнішніх програм** у головному процесі там,
  де їх може дочекатись вікно: yt-dlp.exe розпаковує себе кілька секунд.
  Версію брати через `binaries.ytdlpVersion()` (кеш, асинхронно).
- **Файли користувача — лише через `store.js`** (атомний запис, `.broken`
  замість мовчазного скидання). `playlists.json` — єдине місце, де лежать
  незавантажені треки плейлистів: втрата = безповоротна.
- **Пошук скасовний** (`searchId` + реєстр `running`); SoundCloud — окремим
  викликом, бо повільний; одне впале джерело не валить решту (`allSettled`).
- **Нічого не грає саме** після падіння вікна чи запуску (сесія відновлюється
  на паузі). Вікно піднімається після краху не більше 3 разів.
- **Discord** від'єднується, коли нічого не грає, і не під'єднується на старті.
  Вшитий ID додатка не секрет.
- **Бінарники**: порядок пошуку — профіль користувача (`bin/`) → вшиті
  (`resources/bin`, `app/bin`) → `PATH` → типові місця (ffmpeg) / Python-модуль
  (yt-dlp). Оновлений yt-dlp має переважати вшитий; після оновлення —
  `binaries.reset()`; заміна файлу через `.old`.
- **`signAndEditExecutable: false` у `build.win` не прибирати**, поки на машині
  збірки немає права створювати символьні посилання (Режим розробника) —
  інакше збірка падає. Побічно: на exe чужа іконка (причина — в
  ARCHITECTURE.md).
- **Реліз**: версія в `package.json`, `GH_TOKEN` у середовищі,
  `npm run release`, потім **вручну опублікувати чернетку** на GitHub, інакше
  встановлені копії оновлення не побачать. Реліз робить лише власник.
- **Spotify/Apple Music** — DRM: беремо лише назви й шукаємо звук у YouTube
  Music, і інтерфейс чесно про це каже. FLAC свідомо немає.
- Нове джерело пошуку: додай у `DEFAULTS.sources` (`settings.js`) та
  чекбокс у `index.html` — `knownSources` саме ввімкне його старим
  користувачам.
